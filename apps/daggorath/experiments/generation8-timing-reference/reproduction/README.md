# Diagnostic replay requirements

Use the existing [mixed-scene harness](../../mixed-scene-harness/README.md) and its private launcher. Required byte identities are listed in `../artifact-manifest.json`. Do not rebuild or substitute `msharness`, Variant B `dodhbp`, or `dhbpack` when comparing these runs.

The preserved private procedure used MAME 0.289 (`ample-289-u2`), `coco3h`/HD6309E, 2 MB RAM, disposable EOU media and ports, and a generated private `coco3h.cfg` whose `:screen_config` value was `1` (RGB). Verify the generated config before starting the guest. The repository harness's configuration example and launcher document the current launch arguments; local absolute tool and media paths must be supplied privately.

The committed harness observer supplies the narrow `$FF22` PB1 write tap and `video:snapshot_pixels()` completed-frame classifier. Its readiness must be established before the guest workload starts. Identify a positively active graphics interval; do not classify console pixels as heartbeat rasters. Preserve the published frame event times and raw classifications.

For the breakpoint diagnostic, append a **disposable copy** of `diagnostics/stage-3e13d4/diagnostic.lua` to a private bridge script using the preserved `inject-d4.py` as a reference. That source contains original private absolute paths and requires path adaptation in the disposable copy; the archived source must remain byte-for-byte unchanged. Use the shared `diagnostics/stage-3e13d1/linked-map.json` as its linked map: the original D.2, D.3, and D.4 copies were byte-identical. After the broker module and process are positively identified, at authoritative generation 6 read its *current saved* eight-entry DAT image from the process descriptor. Translate each logical code address through the current code-slot bank into bounded physical RAM. Verify linked instruction bytes before automatically arming breakpoints. Do not demand that GP data mappings still equal their initialization image.

Capture generations 7 and 8 only: PB1 edge, broker process-pointer state, `service_heart` entry, `os_clock` entry/return, `F$CpyMem` entry/return, native snapshot entry, and first complete published raster. The breakpoint run is for **control-flow diagnosis**, not strict deadline acceptance. The exact source of the two other pre-service `os_clock()` calls is unresolved. Stop on artifact or byte mismatch. Do not modify guest registers, memory, heartbeat behavior, or production code.

Complete byte-for-byte replay is not established: this archive excludes EOU media, ROMs, MAME, generated modules, save states, and machine-specific launch state. It preserves the source and selected evidence needed to continue the investigation, subject to those external dependencies.

## How to read the evidence

All upstream paths below refer to commit **`f470fa52eb172b59b22c1b722074998cb42de9b1`**. Relationship describes **upstream relative to the specified EOU source variant**: “likely descendant” means upstream appears to continue that source family; “diverged” means material differences exist without a proven linear ancestry. “Same” is explicitly scoped to the compared routine body, never silently to an assembled module. “EOU-specific” and “upstream-only” describe observed scope in these collections, not exclusive authorship or the entire ecosystem. “Unknown” is intentional when the evidence is insufficient.

Runtime column format is **module: bytes / decimal edition / hexadecimal CRC**. These are the earlier verified EOU observations in [RUNTIME_MATCHES.md](RUNTIME_MATCHES.md), which also preserves type/language, attribute/revision, timestamps and full ident output. Ten identities have byte-identical bundled binary matches; **no editable source was rebuilt**, and no upstream binary was compared with live RAM. An edition match alone is insufficient.

### Documented shared ancestry

[Commit 732cb596f280ce9b867eb6e8e7d4102a61bdb144](https://github.com/nitros9project/nitros9/commit/732cb596f280ce9b867eb6e8e7d4102a61bdb144), 2023-12-18, explicitly integrates EOU 1.0.0 and Beta 5/6 changes. Its message and changed paths identify IOMan, kernel, SCF, PipeMan, CoWin/VTIO, GrfDrv and definition changes. It also records corrections to a 6809 F$Chain optimization and a misaligned 6309 conditional. This is stronger evidence of shared ancestry than similar filenames. It does **not** establish that every loose EOU file is exactly the imported revision or that every historical implementation is correct.

## Changes with directional evidence

- **New upstream window service:** [level2/coco3/modules/co3hires.asm](/Volumes/SEDONA/Projects/nitros9-reference/level2/coco3/modules/co3hires.asm) is upstream-only relative to the inspected EOU VTIO/CoWin pair. Its 2026-07-15 header and commit `03e6fdbd` document shared HiRes service extraction. Recipe inclusion and changed callers establish a real dependency, not merely a new filename.
- **New upstream RBF repair:** commit `14e9394a95fdce57e1908eeded2c3c2974577e78` changes post-park lock retry to reload X:D, where the EOU candidate reloads only A. This is a concrete newer implementation to study; it does not establish a fix for every issue mentioned in EOU's RBF header.
- **New upstream DriveWire repair:** commit `b6f7cc95fb6b8c9ac88adbcc8e28f8e4974d9f20` adds the remaining-open-path check before closing the channel in SCDWV. No current EOU runtime DriveWire execution was tested.
- **EOU SDC improvements absent from this upstream driver:** `/dd/SOURCECODE/ASM/NITROS9/GIMEX/llcocosdc_ver101.asm` has `V.Response` buffering before restoring MPI selection and GIMEX speed handling. Header dates/credits identify 2022-08-26 Bill Nobel and 2023-09-10 Darren Atkinson changes. Upstream `llcocosdc.asm` lacks these particular mechanisms. This is source evidence of a difference, not a new live hardware validation.
- **EOU-specific environment:** installed module selection, `montype r`, startup, EOU utilities and frozen shell behavior remain runtime/distribution evidence. Upstream default recipes do not reproduce that distribution automatically.

## Remaining gaps

Exact editable-source → runtime matching needs controlled builds with the correct historical definitions/options and comparison of complete module bytes. It was not attempted. GrfDrv's historical archive remains unreadable in the earlier inspection; the current upstream implementation is a modern reference, not a retroactive match. Application/language sibling repositories, manuals, and complete per-routine ancestry are outside this pass. No source files, media, or reference checkout were changed.
